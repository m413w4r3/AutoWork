**VERIFIED** Alembic head chain is `0001_baseline` -> `0002_c2_experiments`; 0002 declares `revision` and `down_revision` at `backend/migrations/versions/0002_c2_experiments.py:18-20`; frozen 0001 metadata at `0001_baseline.py:38-39`. **INFERENCE — proposed 0003:** add `backend/migrations/versions/0003_external_effect_claims.py`, `down_revision="0002_c2_experiments"`; leave 0001/0002 untouched. Add ORM `models/external_effects.py`, repository `repositories/external_effects.py`, register model import in `migrations/env.py`, expose repository via UOW using the existing shared session.

**INFERENCE — `external_effect_claim`:** UUID PK; restrictive FKs to investigation and, where present, invocation, model turn/run, acquisition attempt, or Retrohunt reservation; family/provider/operation/version; stable effect identity digest and semantic request digest; request/artifact SHA-256 references; occurrence identifier plus non-null occurrence digest; reservation/envelope version and approval reference; state, CAS version, timestamps. Candidate uniqueness: `(investigation_id, effect_key_digest)`; indexes for invocation, family/state, source lineage. Keep credential-bearing request material and signed URLs out of the row. Exact state vocabulary and normalization of source observation references are **UNKNOWN** and require D6 resolution.

**INFERENCE — `external_effect_use`:** UUID PK; restrictive FKs to investigation, consuming invocation, and source claim; source observation/version references and explicit zero-budget reuse semantics; unique `(invocation_id, source_claim_id)` plus investigation/claim indexes. Enforce same-investigation consistency in repository/transaction (or composite FK if the chosen schema conventions support it). Migration should have explicit preflight and exact drift handling per ADR-0007; do not mutate historical migrations or mask drift with `IF NOT EXISTS`.

**UNKNOWN:** exact D6 digest canonicalization, claim states, FK optionality, whether uses represent each reuse occurrence or unique invocation/claim pair, and whether all source types have stable relational rows suitable for direct FKs.

## 7. Bypasses and fail-closed cutover rules

- **VERIFIED** `pre_dispatch_check` is optional and adapters are invoked directly by dispatcher (`investigation_tools.py:415-430,795-805`). **VERIFIED** adapter/transport signatures do not require a permit (`virustotal.py:419-438,831-981`; `shodan.py:133-239`; `bridge_investigator.py:667-678,968-989`; `integrations/models.py:93-120`).
- **VERIFIED** Advisor conditionally invokes `pre_transport_check` (`investigation_advisor_tools.py:1049-1087`); Bridge `before_submission` is optional (`bridge_investigator.py:1197-1208`). Direct caller paths therefore remain possible unless removed or guarded at the actual send boundary.
- **VERIFIED** Dispatcher `_completed` is process-local (`investigation_tools.py:622-628,699-704`) and cannot be durable effect authority.
- **VERIFIED** wrapping only the adapter call misses transport-owned multiplicity: VT route fallback/page/download redirects, Shodan `/api-info`, Retrohunt results pages, Bridge retries/corrections, advisor batches/retries (refs in inventory).
- **INFERENCE** On family cutover, permit acquisition/consume failure, unavailable coordinator, malformed/stale permit, and missing callback must all fail closed. No catch-and-call-old-transport fallback, optional bypass, or legacy direct submission should remain. Local verified reuse is the explicit no-send case and still needs durable lineage.
- **UNKNOWN** any composition roots or non-investigation callers outside the reviewed D6 surfaces that may also instantiate these transports; audit all constructors/imports before declaring whole-repository closure.
