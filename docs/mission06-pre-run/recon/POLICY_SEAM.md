# M06 policy seam: ordinary OSINT investigation approvals

**Scope.** VERIFIED — Read-only reconnaissance at base commit `505c1cd2c525744bee5d768cccc1a830abce2d2b`; no provider, database, object store, Docker, or test execution was performed. The only intended output is this report.

## Verdict

**INFERENCE —** The repetitive interruption is the per-investigation G2 envelope: each ordinary case starts without durable provider/acquisition authority, then an analyst must approve it and later extend it when finite dimensions are exhausted. Tool-level `request_permission` turns that missing G2 or budget into a pause. A single durable, versioned OSINT_OPEN policy scoped to an authority (for example, a tenant or collection) can authorize bounded ordinary passive work for newly created investigations, while G2 remains available for RESTRICTED cases and G3 remains a human sample qualification decision.

**VERIFIED —** Current contracts describe a zero-provider, zero-acquisition, no-external-LLM default and an explicit human G2 approval; the current code also has a no-envelope Bridge path that can permit external LLM use from source disclosure alone. The implementation and written contract therefore disagree and must be reconciled before OSINT_OPEN is enabled (`docs/investigation_governance.md:11-17`; `docs/investigation_api.md:42-56`; `backend/src/cti_app/application/investigation_service.py:2803-2819`).

## Proposed deep module: `OSINT_OPEN` policy

**INFERENCE —** Put one deep policy module at the application authorization seam, used by G2/G3 orchestration and every dispatch/acquisition/Bridge path. Keep storage and identity adapters behind its interface. Suggested small interface:

```text
enum InvestigationPolicyMode { RESTRICTED, OSINT_OPEN }

record PolicyRef { policy_id, revision }
record PolicyRecord {
  ref, mode, scope, active, capabilities, disclosure_ceiling,
  finite_budgets, activation_event_id, content_hash
}

record EvaluationRequest {
  investigation_id, pinned_policy: PolicyRef?, action, source_disclosure,
  sample_disclosure?, requested_budget, actor_context
}
record Evaluation { ALLOW | DENY | NEEDS_REVIEW, reason_code,
                    policy_ref?, reservation? }

evaluate(request) -> Evaluation
```

- **INFERENCE — Mode and scope:** `RESTRICTED` is the default and keeps the current per-investigation human G2 flow. `OSINT_OPEN` is an explicit configured mode scoped to a named tenant/collection or other policy owner; do not make it a process-wide implicit bypass. Define capabilities as an allowlist (passive VT lookup, passive Shodan, Bridge consultation, bounded VT sample download, etc.); active scanning/acquisition stays absent unless separately authorized.
- **INFERENCE — Version and inheritance:** Policy revisions are immutable. Activation creates an append-only event with authenticated activator kind/ID, reason, time, correlation, revision, and content hash. At investigation creation pin `(policy_id, revision)` and persist it separately from any G2 envelope. New investigations inherit the active matching policy; old cases do not get reclassified automatically. A later restrictive revocation applies immediately to pinned work; a policy loosening does not silently expand an existing case.
- **INFERENCE — One evaluator:** `evaluate(request)` is the only authorization decision function used before G2 actions, G3 qualification, Bridge submission, dispatcher invocation, and acquisition adapter entry. It combines pinned policy, current active/revoked state, source and sample disclosure, action capability, G2 ceiling where present, and budgets; returns a reason and policy provenance. `G3 CONFIRMED/REJECTED` still requires a route-authenticated HUMAN actor and evidence/reason. Policy mode never manufactures a G3 or G2 human decision.
- **INFERENCE — Budgets and reservations:** Every capability has finite dimensions and hard config ceilings. Evaluation returns a reservation intent; a repository transaction reserves idempotently against per-investigation and, if needed, scope-wide counters before external execution. Record policy revision/evaluation on the invocation. Exhaustion returns `NEEDS_REVIEW` or `DENY` with a stable reason; do not interpret missing/unknown limits as unlimited.
- **INFERENCE — Revocation and adapters:** Re-evaluate current policy at reservation and immediately before transport. Include policy revision in invocation audit and reconcile any effect whose outcome becomes ambiguous. Keep direct adapter entry guarded by the same evaluator (not only API/UI or dispatcher), so an adapter call cannot bypass the policy. In `RESTRICTED`, preserve existing G2 CAS, budget, TLP, `do_not_submit`, and G3 gates unchanged.

## Risks and unresolved points

- **INFERENCE — Historical reclassification:** Backfilling OSINT_OPEN onto old cases would change the apparent authorization basis for prior actions. Do not auto-upgrade existing cases; pin policy revision at creation and require an explicit audited migration/review for any exceptional case conversion.
- **INFERENCE — TLP downgrade:** Policy must be a ceiling only. Preserve source/sample restrictions, RED and `do_not_submit`; fail closed for unknown TLP. Current external Bridge check rejects RED but does not reject `None`, while VT acquisition rejects unknown TLP (`backend/src/cti_app/application/investigation_service.py:2803-2819`; `backend/src/cti_app/application/investigation_acquisition.py:290-307`).
- **INFERENCE — Revocation race:** A revocation can race a reservation or transport. Use CAS/current-revision checks at reservation and pre-transport; preserve ambiguous-effect reconciliation. An external action already sent cannot be undone.
- **INFERENCE — Budget abuse:** Shared policy budgets can be exhausted by parallel investigations. Use finite per-case and scoped budgets, atomic idempotent reservation, rate limits, and auditable attribution.
- **INFERENCE — Direct adapter bypass:** A dispatcher-only check is insufficient if adapters are callable directly. Recheck at acquisition/provider entry; preserve policy provenance through invocation.
- **VERIFIED — Contract mismatch blocker:** Runtime permits a no-envelope Bridge path under source disclosure while docs say no G2 means no provider permission (`backend/src/cti_app/application/investigation_service.py:2803-2819`; `docs/investigation_api.md:42-56`). **INFERENCE —** Resolve this before relying on policy evaluation as a single source of truth.
- **UNKNOWN — Identity blocker:** Production HUMAN identity uniqueness/attribution was not verified; available static/local providers collapse users to generic IDs (`backend/src/cti_app/api/identity.py:62-105`).
- **UNKNOWN — Deployment state:** No database, runtime configuration, provider, MinIO, or Docker state was inspected; deployed migration head and live identity configuration remain unknown.
