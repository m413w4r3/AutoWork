# R7-S3 — adversarial review of the provisional external-effect seam

**Verdict: `REVISE`.** The one-physical-request consume model is a sound direction, but the selected `send_one(authority, prepared, transport)` contract does not yet establish a mandatory last-mile gate or a lockable state set for all current paths. The two blockers below are design-repairable; implementation is not approved by this review.

**Study point:** `aa0cef3ee07525ca77d6b1358252ebf5735a3dde`, branch `mission03/architecture-design`. This is a read-only review. **VERIFIED** means source or test-surface evidence at that SHA; **INFERENCE** means a failure follows if the proposed seam is implemented as written; **UNKNOWN** means source review cannot establish runtime behavior.

## Ranked findings

### F1 — BLOCKER: caller-supplied transport does not make `send_one` the mandatory physical-send seam

**Evidence.** The selected interface takes a `transport` argument (`DESIGN_OPTIONS.md:294-304`). Today the dispatcher callback is optional and the adapter is entered after it returns (`backend/src/cti_app/application/investigation_tools.py:412-427,779-784`); Bridge's callback is also optional (`backend/src/cti_app/application/bridge_investigator.py:1172-1183,1231-1291`). More specifically, `ModelConversationTurnTransport` calls `ModelConversationService`, then `ModelGateway.execute` calls the model adapter (`bridge_investigator.py:555-565,943-964`; `model_conversations.py:1282-1305`; `model_gateway.py:1161-1179`). `ModelGateway` itself can invoke the adapter again after a verified terminal Bridge failure (`model_gateway.py:1257-1264`).

**Failure scenario.** A caller supplies a different transport, or supplies a wrapper whose `send` method follows redirects, retries, paginates, or calls another raw client. The coordinator may consume once and believe it authorized one request while the supplied code emits a different request or multiple physical sends. A gate placed around `ModelConversationTurnTransport.submit` would also miss the retry inside `ModelGateway.execute`.

**Guarantee not assured.** “One consume authorizes one exact physical request” and “every direct raw entry fails closed.” This also prevents the deletion test from proving that the former read-then-dispatch logic disappeared.

**Required oracle.** Parameterize every raw investigation transport entry with no, copied, stale, wrong-route and wrong-digest permit; assert zero fake calls. At the final HTTP/model adapter boundary, record the method/target/body and assert exact digest equality and one call. Include the `ModelGateway` terminal-failure retry, redirect, ticket/fallback and page paths. A fake does not establish provider receipt.

**Possible fix.** Remove per-call caller-supplied `transport`. Resolve an immutable, server-composed route/transport from a coordinator-owned route ID and version. Keep test substitution at composition. Make each investigation physical-send method require a coordinator-minted one-use permit and prepared request; enforce it at the final send boundary. Disable hidden retries/redirects or surface each physical request through a fresh consume. Integrate the ModelGateway retry loop at that boundary or disable its internal retry until it can consume separately.

### F2 — BLOCKER: the consume lock set is not reconciled with the persisted stop, budget and Bridge state

**Evidence.** The selected order is envelope → invocation → reservation → dispatch → family attempt → Bridge turn → ModelRun, with a conditional stop/cancel note (`DESIGN_OPTIONS.md:315-321`). On the ordinary operator path, `execute_tool_call` reserves in `envelope.budget`, saves the envelope, and commits before dispatch (`backend/src/cti_app/application/investigation_service.py:1110-1153`; repository serialization at `backend/src/cti_app/infrastructure/database/repositories/investigation.py:1470-1492`). The stop check is a separate read before dispatcher entry (`investigation_service.py:1155-1177,2620-2623`); stop is persisted in the separate, versioned `investigation_working_states` row (`backend/src/cti_app/infrastructure/database/models/investigation.py:677-719`; repository CAS at `repositories/investigation.py:1368-1411`). There are also normalized budget record/reservation/amount tables (`models/investigation.py:585-675`; `repositories/investigation.py:1505-1577`), so the reservation source must be stated per execution path. For Bridge, the turn/run are created in `ModelConversationService` before gateway execution (`backend/src/cti_app/application/model_conversations.py:1282-1305`), and the existing gateway accepts an initial `RUNNING` run only while `submission_state` is `NOT_SUBMITTED` (`backend/src/cti_app/application/model_gateway.py:1051-1061`), then starts a submission attempt in its own UOW (`model_gateway.py:1140-1144`).

**Failure scenario.** Stop is committed after the existing stop read but before consume; without locking/reloading the working-state row, the send proceeds. Or consume updates the ModelRun to submission-in-progress, then the current ModelGateway interprets that as an already-started ambiguous submission and refuses; alternatively, a coordinator above the gateway leaves the ModelRun unchecked while the gateway issues an unconsumed retry. A path using normalized budget rows may bind the wrong reservation if the transaction assumes all reservations live in the envelope JSON.

**Guarantee not assured.** Revocation/stop-first denial, `RUNNING → NEEDS_REVIEW` exclusion for all owners, correct reservation/accounting linkage, Bridge attempt uniqueness, and deadlock-free ordering across all writers. “Include stop/cancel if separate” is not a lock contract; current state has a row version and `stop_reason`, not a separate stop-generation field.

**Required oracle.** Independent PostgreSQL sessions: stop-first versus consume; invocation A pauses before consume while B commits `NEEDS_REVIEW`; envelope revoke-first and consume-first; Bridge turn/ModelRun state changed before consume; and acquisition/Retrohunt slot races. Assert zero egress for denied consumes, the one allowed consume-first request, no lock held during transport, correct budget rows, and no deadlock. Exercise the production UOW/repositories, not an in-memory fake.

**Possible fix.** Specify the authoritative reservation table and binding separately for operator, Bridge, Retrohunt and acquisition; for operator tools, consume from the locked envelope snapshot as currently written. If another reservation repository is authoritative on a path, lock its record and ordered amount rows in the same transaction. Add `investigation_working_states` to the consume contract whenever stop blocks egress, checking its current version/stop value under lock. Make the coordinator and ModelGateway share the same transaction/permit protocol: consume must check and transition the exact Bridge turn/run, and the final model adapter must accept only that permit. Publish one global lock order and update every writer/reconciler touching those rows to follow it.

### F3 — HIGH: cross-invocation identity, occurrence and reuse need a durable claimant/link contract

**Evidence.** The selected descriptor names semantic/request digests, versions, `occurrence_id`, `parent_effect_id`, `step`, `reuse_policy` and evidence refs (`DESIGN_OPTIONS.md:298-314`), but does not name a unique-key definition or a reuse/claimant link. M3 distinguishes client `operation_key` from effect identity and says generic cross-invocation lineage/budget is unknown (`_work/M3_S3_DIAGNOSIS.md:71-93,217-233`). The designer options that detail reuse use a separate use/claimant link (`_work/D6_S3_C_MIGRATION.md:320-328,422-429`; `_work/D6_S3_D_RELIABILITY.md:303-316`). A normalizer-version bump is explicitly a compatibility risk in C (`_work/D6_S3_C_MIGRATION.md:610-613`).

**Failure scenario.** Two client keys create two dispatch rows for the same semantic request and both send. Or invocation B reuses A's response but the only dispatch row still points to A, leaving B's use, source observation and zero budget delta unauditable. A normalizer version change produces a new effect key and silently permits an equivalent request to be sent again. A fresh random occurrence on each retry can bypass same-occurrence dedupe, including after an ambiguous result.

**Guarantee not assured.** One winning default claim across client keys; explicit and stable occurrence semantics; source-linked reuse; no second charge; and no implicit duplicate send across normalizer versions or legacy rows.

**Required oracle.** Two PostgreSQL sessions use different client keys for identical prepared input: one dispatch/send only. Then invocation B reuses A's terminal successful result with a durable source-claim/observation link, unchanged source ownership, zero additional charge and no transport. An ambiguous A must never be reused or resent. Repeat across a normalizer-version transition and prove no fresh send without an explicit reviewed compatibility/occurrence rule.

**Possible fix.** Define a versioned, investigation-scoped default unique claim and a unique `(effect, occurrence_id)` claim; make page/retry/correction/poll occurrences stable and server/workflow-owned, never minted afresh by generic replay. Add a claimant/use row for every consumer. Separate semantic identity from serializer/normalizer version where equivalence is intended, with an explicit version migration/alias rule; a version bump alone must not authorize another send. Do not infer old effect claims from raw `normalized_parameters`.

### F4 — HIGH: post-consume recovery and family budget/evidence settlement are named but not fully specified

**Evidence.** The selected state list distinguishes PREPARED, CONSUMED, success, confirmed-not-sent and review, and promises CAS reconciliation (`DESIGN_OPTIONS.md:305-310`), but does not state the full CAS transition graph or lost-commit-ack/late-response rules. The brief requires unknown post-consume outcomes to remain review-only and forbids silent evidence loss/truncation (`_work/D6_BRIEF_S3.md:94-106`). Acquisition currently has both envelope reservation handling (`backend/src/cti_app/application/investigation_acquisition.py:343-367`) and separate VT-read/hit budget consumption (`backend/src/cti_app/application/sample_acquisition.py:349-367`); verified reuse returns zero VT/download units (`investigation_acquisition.py:201-243,245-288`).

**Failure scenario.** The consume commit succeeds but its acknowledgement is lost; a retry reconstructs a permit. A partial/late provider response is dropped when the dispatch changes state. Acquisition charges the generic operation reservation and the separate VT-read/hit ledger twice, or releases one ledger based on an adapter exception even though bytes may have been sent. Bridge's logical `BRIDGE_TURNS` charge is duplicated per physical retry, or measured usage is settled twice.

**Guarantee not assured.** No double-submit after consume, exact late-response correlation, typed proof before release, one-time budget settlement, retention of partial response evidence and complete authorized request/evidence bytes.

**Required oracle.** Fault-inject before consume, after consume commit with lost acknowledgement, after one fake accepted request with dropped response, during partial acquisition bytes, and on late response after reconciliation. Assert a single dispatch/send, `NEEDS_REVIEW` where ambiguous, retained reservation until explicit CAS reconciliation, one Bridge logical charge plus once-per-dispatch measurements, and exact evidence artifacts/refs with no truncation. No adapter-provided boolean/string may prove not-sent.

**Possible fix.** Freeze a complete state/event transition table: consumed acknowledgement uncertainty never reconstructs a permit; late results attach to the exact dispatch/request digest by CAS; partial bytes/responses are retained as review artifacts; only framework-owned pre-send proof yields `CONFIRMED_NOT_SENT`; and explicit reconciliation never resets the old dispatch. Add unique settlement/usage keys. Document which acquisition ledger is charged at consume and how its VT-read/hit amounts relate to the outer reservation and sample-reuse path.

## Explicit attack-scenario answers

1. **Direct entry / transport argument — VERIFIED today, not closed by the selected signature.** Current registry and Bridge callbacks are optional, and adapters have provider paths below them (`investigation_tools.py:412-427,779-784`; `bridge_investigator.py:1172-1183,1231-1291`; `_work/M1A_EXTERNAL_EFFECTS.md:11-19,29-37`). A caller-supplied `transport` is itself a bypass seam unless the coordinator resolves a frozen route and that route's final send enforces the permit. The ModelGateway retry means a top-level model transport may emit more than one request per call (`model_gateway.py:1257-1264`).
2. **Forged/copied/replayed/stale/misbound permit — INFERENCE, not guaranteed by the interface alone.** Bind issuer, dispatch ID, owner/invocation, investigation, route/provider, envelope version, exact request digest and one-use nonce; consume the nonce atomically at the raw send boundary. The DB row is authoritative; never accept a public data-only permit constructor or re-create a permit after an uncertain commit.
3. **Same effect / multiple client keys / occurrences / versions — PARTIAL.** Default identity must dedupe across client keys; an intentional poll/refresh/page/retry must have a stable, workflow-authorized occurrence and parent/step. Ambiguous outcomes cannot mint a new occurrence. A normalizer-version change needs an explicit cross-version compatibility rule so equivalent requests do not silently acquire a fresh claim.
4. **Prepared versus emitted bytes / hidden requests — PARTIAL, with one verified nested retry.** Persist immutable method/target/body or safe artifact ref and digest; compare at the final HTTP/model send. A transport can otherwise mutate after an earlier digest check. Each pagination page, retry, redirect, ticket, fallback and Bridge correction is a new consume. `ModelGateway.execute` has an internal retry (`model_gateway.py:1161-1179,1257-1264`); SDK/proxy retry behavior remains **UNKNOWN** until traced and tested.
5. **Envelope change/revocation — APPROVED AS A LINEARIZATION RULE, conditional on F2.** Consume locks/reloads the same envelope row as revoke. Revoke-first denies; consume-first authorizes exactly that request, even if the socket write is later; every subsequent request must consume again. No SQL lock crosses transport (`_work/M3_S3_DIAGNOSIS.md:301-326`).
6. **RUNNING → NEEDS_REVIEW / Bridge retries — REQUIRED, not implemented.** Consume must reload and require the operator invocation still `RUNNING`; a paused worker then gets zero egress. Bridge attempt/run must be part of the same transaction and each retry/correction its own consume. Existing Bridge turn/run is persisted, but the ModelGateway's own state/retry logic must be integrated, not wrapped above it (`model_gateway.py:1051-1061,1257-1264`).
7. **Crash/ack/late/partial response — PARTIAL.** Before consume, no permit means no egress. After consume, crash before send, after send, lost commit acknowledgement, timeout, cancellation and partial/ambiguous response all remain review-only absent trusted proof. Late output must resolve that exact row by CAS; no replay may resend. Preserve partial artifacts; don't equate “no response” with “not sent.”
8. **Cross-invocation result reuse — NOT SPECIFIED ENOUGH.** Reuse only terminal, complete, exact-identity results permitted by per-operation policy. Add a use/claimant link to source dispatch, source invocation, observations/artifact versions and consumer invocation; original provenance stays unchanged and second external budget delta is zero. Historical rows without proof are not reusable/backfilled.
9. **Budget — PARTIAL.** `BRIDGE_TURNS` is a logical reservation once; measured usage belongs once to each physical dispatch. Bind Retrohunt slot and generic reservation in the same consume. Acquisition must account for the outer reservation and its separate VT-read/hit ledger without double charge; verified local reuse is zero network budget. Ambiguity retains budget; only proven no-send or explicit reconciliation settles/releases it.
10. **Evidence/disclosure — POLICY SET IS RIGHT, PERSISTED SOURCE SET NEEDS CLOSURE.** Recheck G2/provider scope, TLP, DNT, `external_llm_allowed`, sample restrictions, exact human approval/version and stop at consume. `advisor.consult` is a model submission internally, despite its registered `EXTERNAL_READ` label (`investigation_advisor_tools.py:3395-3409`). Keep full authorized evidence and omission reasons; never store AutoWork credentials/signed URLs in identity/logs. Signed acquisition targets need an in-memory digest/route design if the exact URL is secret-bearing.
11. **Lock order / real repositories — PARTIAL.** Operator reservation is in the locked envelope `budget_snapshot` on `execute_tool_call` (`investigation_service.py:1110-1153; repositories/investigation.py:1470-1492`), while separate normalized budget rows also exist (`models/investigation.py:585-675`). Stop is separately persisted as `investigation_working_states` (`models/investigation.py:677-719`). Bridge run/turn use separate repositories/UOWs today. The proposed order must name exact path-specific rows, include stop when it blocks dispatch, and make all writers follow one order; current DB behavior is **UNKNOWN** until the two-session oracle runs.
12. **Migration/rollback/first slice — CONDITIONALLY SOUND.** Add after the repository head `0002_c2_experiments` (`backend/migrations/versions/0002_c2_experiments.py:18-20`); never edit `0001` or rewrite `0002` (`backend/AGENTS.md:19-31`; `docs/adr/ADR-0007-frozen-baseline-and-c2-migration.md:19-45`). No backfill from raw parameters. Cut over by family only after direct-entry guards exist; drain/fence old workers; deny all on failure; rollback only to permit-aware code and keep history. No live database/head state was inspected.
13. **Deletion test / source of truth — PARTIAL.** Delete the optional read-then-dispatch callbacks only after all physical paths use the gate and direct entry without permit fails closed. One dispatch row may be authoritative for send permission; it must not replace invocation, budget, Bridge, Retrohunt, acquisition or observation state. Add claimant/use lineage rather than duplicating reuse truth. Existing provider-specific policy/domain checks stay in their owning modules.
14. **Tests that miss bypass / required PG oracles — VERIFIED.** M2-A notes that adapter/client MockTransport tests and `test_concurrent_operation_key_replay_creates_one_invocation` can stay green while a raw send bypasses the gate (`_work/M2A_TEST_SURFACE_EXTERNAL.md:119-126`). Before enablement require independent-session PostgreSQL barriers for: RUNNING→NEEDS_REVIEW before consume; revoke-first and consume-first; same effect under distinct client keys; permit second-use/misbinding; consume acknowledgement loss/crash; Bridge turn/run and stop changes; budget settlement/reuse lineage; and lock/deadlock order. The no-permit direct-entry zero-call tests must cover VT, Shodan, Retrohunt, acquisition, advisor and Bridge (`M2A_TEST_SURFACE_EXTERNAL.md:48-82`).

## Disposition

**Approved direction:** a short PostgreSQL consume commit is the only permission to send; no DB lock spans I/O; one physical request per consume; revocation before consume denies and after consume cannot retract that single request; ambiguous consumed outcomes are review-only; advisor is treated as a model submission; no provider idempotency assumption; additive migration and no raw-parameter backfill.

**Conditional on revision:** remove per-call `transport`; define frozen route ownership and final send enforcement; freeze unique claim/occurrence and result-use schemas; include stop and exact budget/Bridge/family rows in a feasible lock transaction; define recovery and budget/evidence settlement; prove direct-entry and PostgreSQL race oracles before enabling each family.

**Must not be implemented yet:** production egress through this interface, any migration/cutover, cross-invocation reuse of unproven historical results, or rollback to a binary that can send without a permit. Keep every uncut family denied when deploying the gate; do not treat an in-memory permit or fake transport as PostgreSQL/provider evidence.

**Smallest safe first slice after M7 approval:** a test-only `vt.file_report` route with prepared identity, one dispatch row and final permit-required transport, leaving production sends disabled and all other families deny-all. **First RED oracle:** with two independent PostgreSQL sessions, A commits `RUNNING` + exact reservation + prepared request and pauses before consume; B commits `NEEDS_REVIEW`; A resumes and must get no consume/permit and the fake VT transport count must remain zero. Add the direct raw VT no-permit zero-call assertion before any family enablement.
