# M1-C — Investigation persistence, context, and audit flow

**Scope:** read-only map at source SHA aa0cef3ee07525ca77d6b1358252ebf5735a3dde on branch mission03/architecture-design. No production code or tests were changed. No tests were run.

**Vocabulary:** module, interface, implementation, seam, adapter, depth, leverage, locality.

## Findings at a glance

- **VERIFIED:** PostgreSQL rows and immutable canonical blobs are the primary source. Tool invocations, working state, governance envelope, and budget are mutable versioned records; observations are immutable records linked to blob IDs and SHA-256; findings and opinions retain append-only versions. The RUN_* files are derived export artifacts, not canonical evidence.
- **VERIFIED:** source-bounded keyset page creation, cursor encoding, page hashes, and omission-manifest validation are shared in context_pagination.py. The SQL adapters and in-memory adapters share the repository Protocols, but only SQL pages bound database reads.
- **VERIFIED:** the full Bridge context and the operator section reader can recompute identically named sections from different source selections. In particular, the full context initially reads all finding versions, while the paged “findings” section requests latest-only; the full evidence index is ID-sorted, while the paged evidence index is observed-time/ID keyset ordered.
- **VERIFIED:** RUN_EVENTS is a deterministic projection of a read-only database snapshot, not a stored transition log. State and invocation updates overwrite current rows; the export reports their current snapshots and versions. Historical transitions are unavailable unless represented in append-only records.
- **VERIFIED:** the audit export is a CLI, not an investigation HTTP route. RUN_INDEX.json contains canonical retrieval references, including linked model-conversation-turn blob references, but no message bodies, payloads, or signed URLs. The separate model-conversation turns route can return input/output text.
- **UNKNOWN:** the production audit snapshot adapter explicitly says its PostgreSQL runtime behavior has not been exercised; unit tests use synthetic AuditSourceSnapshot values. The PostgreSQL integration tests listed below were inspected, not run.

## Textual call graph

1. **Operator tool request → state CAS → invocation journal.** POST operator tool route passes to OperatorToolInvocationService.invoke (backend/src/cti_app/api/investigation.py:1461-1517; backend/src/cti_app/application/operator_tool_invocation.py:700-761). It canonicalizes schema version and hashes the idempotency key plus payload into operation_key. _invoke_locked checks the current working-state version, appends an operator action with save_if_version, then delegates execution (operator_tool_invocation.py:823-878, 926-927, 1031-1103). The operation-key uniqueness/idempotent replay contract is in the repository Protocol and adapters (investigation_persistence.py:38-61, 294-337; repositories/investigation.py:159-177, 243-314).

2. **Invocation → effect → observation blob/reference.** InvestigationService.execute_tool_call creates or reuses a PENDING invocation, persists RUNNING with an invocation version increment, reserves/commits budget, then commits before dispatch (investigation_service.py:1007-1153). The production observation writer sanitizes the result, stores canonical JSON in the investigation-evidence bucket, checks the returned SHA-256, and constructs an observation pointing at that blob (investigation_service.py:160-240; evidence_recorder.py:98-187). EvidenceObservationRepository.append_if_absent persists the immutable observation; the terminal invocation version stores response_refs and is committed after budget completion (investigation_service.py:1269-1319; repositories/investigation.py:432-487, 490-521). ToolInvocation.response_refs are explicit links; export ordering is not used as causality.

3. **Canonical records → full context projection.** ResearchContextBuilder.build resolves the exact synthesis artifact, fetches descending source pages for observations, findings, and invocations, then projects summaries, indexes, tool coverage, state, opinion notes, and pagination_manifest (research_context_builder.py:1074-1168, 1302-1429). MAX_CONTEXT_SOURCE_PAGE is 256; the full prompt evidence cap is 16, index cap 200, tool coverage cap 200, finding cap 200, and total context byte cap 256 KiB (research_context_builder.py:92-119). Context bytes are canonicalized and hashed for pending Bridge submission; a pending context is stored in immutable artifact storage and its blob ID/SHA are CAS-saved in working state (investigation_service.py:557-631; ProductionArtifactContextSnapshotRepository at 243-271; domain/investigation_state.py:67-163).

4. **Operator context → paginated projections.** GET /api/investigations/{id}/operator/context delegates to get_context, which verifies expected state version/SHA, rebuilds the context, and returns a separate context_sha256 (api/investigation.py:1162-1210; operator_tool_invocation.py:350-434). GET /operator/context/section/{section} validates state CAS/cursor and delegates source-paged sections to read_context_section_page (api/investigation.py:1410-1458; operator_tool_invocation.py:436-578; research_context_builder.py:2236-2412). SQL repository adapters seek by (timestamp, UUID) and fetch limit+1 rows; context_pagination.make_keyset_page builds chained page hashes and the next position cursor (repositories/investigation.py:145-156, 188-241, 377-430, 546-616; context_pagination.py:608-748).

5. **Canonical rows → audit snapshot → files.** export_investigation_audit.py calls read_investigation_audit_snapshot, then write_audit_bundle (backend/scripts/export_investigation_audit.py:40-76). The reader uses one PostgreSQL REPEATABLE READ READ ONLY transaction and loads invocation, observation, finding, experiment, working-state, envelope, budget, opinion, decision, input-pack, candidate, association, and directly linked pivot conversation/turn/model-run records (infrastructure/database/investigation_audit_reader.py:48-164, 167-209). It reads advisor-call blobs after the SQL snapshot and projects only hash-verified metadata (investigation_audit_reader.py:178-209). project_audit_events makes stable event snapshots and an audit.snapshot digest/count record (investigation_audit_export.py:856-886, 1668-1776). build_audit_bundle derives RUN_EVENTS.jsonl.gz, RUN_INDEX.json, RUN_TRACE.md, and RUN_MANIFEST.json; write_audit_bundle locks the output directory, writes events as the checkpoint first, and atomically writes each file (investigation_audit_export.py:2568-2659).

## Interfaces and seams already present

- **Persistence seam — reasonably deep for record operations.** application/investigation_persistence.py defines Protocols for invocation, observation, finding, experiment, opinion, envelope, budget; investigation_state.py defines working-state and context-snapshot Protocols. SQLAlchemy and in-memory adapters satisfy these interfaces. The interfaces carry ordering, paging, idempotency and version/CAS behavior, not just get/save calls. SQL implementation details stay in repositories/investigation.py; domain entities and invariants stay in domain/investigation.py and domain/investigation_state.py.
- **CAS locality.** Working-state get/save_if_version has one interface; in-memory adapter serializes with asyncio.Lock, while SQL loads FOR UPDATE and checks the expected version and exact +1 transition (investigation_state.py:21-27, 65-86; repositories/investigation.py:1356-1411). State payload decoding cross-checks JSONB against indexed columns (1264-1340). Finding append_version similarly checks supersedes and prior version, then stores ordered refs (repositories/investigation.py:618-703).
- **Pagination seam — shared primitives, not a single full projection interface.** context_pagination.py owns the cursor/page/manifest data shapes, canonical page SHA, source_ref, validation and generic page construction. SQL repositories own database seek predicates/count/order; ResearchContextBuilder owns mapping source records into evidence/finding/tool page rows. API route delegates to OperatorToolInvocationService.
- **Context and audit projection.** ResearchContextBuilder.build is the main module that hides source collection and Bridge context projection. AuditSourceSnapshot + project_audit_events/build_audit_bundle form a pure export projection seam with no database dependencies. The DB snapshot loader is a concrete PostgreSQL adapter, not a selectable reader Protocol.
- **Callers still own recomposition details.** ResearchContextBuilder._page_source has a list fallback that materializes a whole repository and marks it source_bounded=false (1661-1729). The builder also constructs source and materialized omission manifests, reconciles them after budget reduction, maps source pages, and rebuilds offset/keyset pages (1432-1658, 1732-1923, 2236-2518). OperatorToolInvocationService separately builds materialized-section page proofs and checks keyset proof consistency (operator_tool_invocation.py:137-293, 580-698). The shared page module therefore concentrates proof primitives, while source selection and projections remain caller-owned.

## Ordering, cursors, omissions, idempotency, and known recomposition differences

- **VERIFIED — SQL ordering/keyset:** invocations use (created_at, id), observations use (observed_at, id), findings use (created_at, id); both sort columns are ordered in the same direction and UUID breaks timestamp ties. Descending seek means sort key/id less than the pivot; ascending means greater than it (repositories/investigation.py:145-156, 188-241, 377-430, 546-616). Source page limit is 1..1000 at the repository seam; operator section API further limits to 1..20 (api/investigation.py:1414-1423; operator_tool_invocation.py:482-483).
- **VERIFIED — cursor rules:** keyset cursor includes version, kind, section, investigation ID, sort key, item ID, previous page SHA, direction, and optional context SHA; it is base64-encoded but deliberately unauthenticated. Decoder binds it to section/investigation/direction and supplied context SHA. The service requires expected working-state version and SHA when a cursor is supplied, while legacy numeric offsets remain accepted (context_pagination.py:82-162; operator_tool_invocation.py:454-509).
- **INFERENCE — not a source snapshot cursor:** the operator cursor context SHA is the current working-state SHA, not a database collection snapshot. An observation can be appended while the working state remains unchanged; the PostgreSQL integration test explicitly does this and then reads a page under the same state CAS (test_operator_context_summary_postgres.py:108-144). SQL pages query current rows per request, so a multi-page walk does not promise a frozen source set. Stable tuple seek prevents offset shifting, but concurrent inserts can change total or which rows are seen.
- **VERIFIED — omission accounting:** ContextOmissionManifestEntry requires selected + omitted = total and reason counts = omitted; bounded/unbounded status must agree with unbounded_reason (context_pagination.py:27-57). Source keyset page construction uses PAGINATION for rows outside the source page; source projection splits PAGINATION and NOT_SELECTED; budget reduction reconciles BUDGET; materialized sections use SOURCE_NOT_PAGINATED; article/state projections can use NOT_SELECTED (research_context_builder.py:1432-1483, 1732-1836, 2440-2456; operator_tool_invocation.py:137-244). SENSITIVITY and TOMBSTONE are defined enum values, but are not used by these projection call sites. RUN_INDEX and RUN_MANIFEST make missing references/fields observable as unavailable_resources or UNKNOWN gaps.
- **VERIFIED — idempotency/CAS:** invocation operation_key is unique and content conflicts are rejected; updates must preserve identity and increment version by one. Observation ID reuse with different content is rejected; SQL also deduplicates on investigation/SHA/kind/object identity. State saves are equal-state idempotent and otherwise require exact expected version plus one. Findings are append-only with a supersedes chain. Pending Bridge context ID/SHA is stored with state, and resume verifies blob bytes against the stored SHA before parsing (repositories/investigation.py:243-314, 432-487, 618-672, 1368-1411; domain/investigation_state.py:90-118, 158-163; investigation_service.py:557-570).
- **VERIFIED — different projections under the same section label:** full context build calls findings.page_for_investigation without latest_only, while the paginated findings section passes latest_only=true. Thus build context can include superseded finding versions while the section reader emits latest versions only (research_context_builder.py:1101-1110, 2334-2355; repositories/investigation.py:546-580). Full context evidence_index is sorted by observation UUID string and capped by count/bytes; paged evidence_index follows observed_at/id descending and projects each page item independently. This changes order and can change which entries fit a budget (research_context_builder.py:3186-3214, 2301-2333). These are verified code differences; whether they violate intended caller semantics is an open question.
- **VERIFIED — bounded input and truncation visibility:** full context reads at most 256 newest source observations/findings/invocations per initial build. It marks source pagination, not-selected, and post-projection budget omissions in the manifest. Evidence summaries clip each text to 600 characters with an ellipsis; section flags and counts track row omission, not per-summary clipped character counts (research_context_builder.py:92-119, 1091-1158, 1317-1368, 3148-3183; _truncate at 4085-4089). latest_tool_results is capped at 16 by contract and implementation, with no dedicated latest_tool_results_truncated field; tool_coverage is a separate larger summary with its own truncation flag (investigation_contracts.py:212-245; research_context_builder.py:3524-3579). Source and projection truncation are usually represented; per-item text reduction is only signaled by the visible ellipsis, and the latest-results subset has no separate count.
- **VERIFIED — export is a snapshot projection:** invocation event contains status-at-snapshot, current reserved/consumed amounts, current response refs, current version, and explicit UNKNOWN transition history. State event hashes current questions/hypotheses/action history and current version. Export cannot reconstruct prior invocation/state/budget transitions from those rows (investigation_audit_export.py:900-988, 1002-1055, 1624-1665). Findings, opinions and experiments contribute their stored versions; events are sorted by timestamp/type/record/event ID and the code states order is not causality (1668-1776).
- **VERIFIED — message/index references:** only pivot_conversation_id is read for this investigation snapshot. Its turns are ordered by sequence in the repository and linked ModelRuns are de-duplicated by ID. RUN_INDEX records turn input/output blob IDs and SHAs as references and marks unavailable when direct pivot turns or linked runs do not exist (investigation_audit_reader.py:116-136; investigation_audit_export.py:1846-2108). ToolInvocation has no direct ModelRun foreign key; explicit observation response refs and advisor-call metadata are the available links.

## Open questions

- Should the full-context findings section include every finding version, or only current versions as the paginated findings section does?
- Should full and paged evidence_index share one ordering and byte-selection policy, or is UUID order in the compact full context intentional?
- Is a working-state SHA intended only as a caller CAS, or should multi-page source reads be tied to a stable source snapshot/version?
- Should latest_tool_results expose a dedicated truncation count/flag, given tool_coverage is a separate projection?
- Should RUN_INDEX be referred to as the message index in downstream consumers, or only as a general canonical-resource reference index?
- The offline suite does not establish the production PostgreSQL audit reader behavior. Which permitted PostgreSQL test should own that adapter contract?

## Next permissible action

No architecture decision is made here. The next design phase can resolve the open semantic questions against the tested contracts and decide whether the current differences are intentional.
