## Call graph and boundary crossings

1. **Canonical investigation state → tool admission.** The composition root wires `advisor.consult` only when the configured turn transport exists: [`investigation_composition.py:1539-1559`](backend/src/cti_app/application/investigation_composition.py); runtime conditionally supplies `ModelConversationTurnTransport` at [`investigation_runtime_ports.py:831-843`](backend/src/cti_app/infrastructure/investigation_runtime_ports.py). The tool schema and consultation/reparse names are in [`investigation_advisor_tools.py:74-85`](backend/src/cti_app/application/investigation_advisor_tools.py). `InvestigationAdvisorTool.execute` validates the request and loads the case snapshot/evidence inputs at [`investigation_advisor_tools.py:164-313`](backend/src/cti_app/application/investigation_advisor_tools.py). This is the entry from canonical investigation repositories into the application module.

2. **Case state → evidence projection and selection.** `_consultation_data` builds a consultation-specific projection from article claims, working state, observations, findings, measurements, and opinion targets at [`investigation_advisor_tools.py:1605-2240`](backend/src/cti_app/application/investigation_advisor_tools.py). Observation bytes are read only through blob descriptors whose size and SHA-256 are checked before JSON content is projected at [`investigation_advisor_tools.py:2682-2717`](backend/src/cti_app/application/investigation_advisor_tools.py); excerpts are extracted at [`investigation_advisor_tools.py:2670-2680`](backend/src/cti_app/application/investigation_advisor_tools.py). Selection and content extraction are separate from the dossier module.

3. **Projected evidence → dossier.** `build_advisor_dossier` extracts recognized content fields, applies task/relevance selection, handles explicit references and contradictions, selects opinion text/measurements/findings, then creates aliases and a manifest at [`advisor_dossier.py:114-301`](backend/src/cti_app/application/advisor_dossier.py) and [`advisor_dossier.py:304-939`](backend/src/cti_app/application/advisor_dossier.py). The resulting dossier carries selected-source identities and hashes; it is a projection, not a replacement for canonical observations. The application then performs the completeness/contradiction check against the dossier and exact prompt at [`advisor_dossier.py:942-1687`](backend/src/cti_app/application/advisor_dossier.py).

4. **Dossier → disclosure checks → rendered prompt.** Operational-secret redaction and residual-secret refusal happen before transport at [`investigation_advisor_tools.py:415-435`](backend/src/cti_app/application/investigation_advisor_tools.py), using [`publication_secret_guard.py:118-153`](backend/src/cti_app/application/publication_secret_guard.py). Case-level external disclosure permission is evaluated by [`investigation_service.py:2554-2570`](backend/src/cti_app/application/investigation_service.py); sample-linked evidence and findings are separately filtered at [`investigation_advisor_tools.py:323-413`](backend/src/cti_app/application/investigation_advisor_tools.py) and [`investigation_advisor_tools.py:5898-5932`](backend/src/cti_app/application/investigation_advisor_tools.py). The dossier manifest/text and byte counts are attached, and `_fit_advisor_prompt` plus completeness gates either admit the request or persist a preflight refusal at [`investigation_advisor_tools.py:436-551`](backend/src/cti_app/application/investigation_advisor_tools.py). `_prompt` serializes the actual `advisor-wire.v1` request, including the rendered dossier text, task, references, assertions and output contract, at [`investigation_advisor_tools.py:2855-2947`](backend/src/cti_app/application/investigation_advisor_tools.py). `render_advisor_wire_input` is the dossier rendering seam at [`advisor_wire.py:267-273`](backend/src/cti_app/application/advisor_wire.py). This separates extraction, completeness, disclosure, projection and serialization.

5. **Rendered prompt → consultation record → transport.** The exact prompt is SHA-256 identified and archived under `advisor-prompts`; its source refs and reparse context are assembled before submission at [`investigation_advisor_tools.py:568-763`](backend/src/cti_app/application/investigation_advisor_tools.py), with reparse context construction at [`investigation_advisor_tools.py:4188-4225`](backend/src/cti_app/application/investigation_advisor_tools.py). `submit_bridge_consultation_once` is the application transport seam: it performs idempotency, disclosure recheck, pacing/deadline and bounded retry handling before invoking the supplied `BridgeTurnTransport` at [`bridge_investigator.py:248-495`](backend/src/cti_app/application/bridge_investigator.py). Its result carries status, turn identity and raw response bytes/text, or an ambiguous/blocked outcome; ambiguous outcomes do not go to parsing.

6. **Transport adapter → model-conversation persistence and provider boundary.** `ModelConversationTurnTransport` recovers an existing durable turn before submitting and uses a stable investigation conversation identity at [`bridge_investigator.py:555-620`](backend/src/cti_app/application/bridge_investigator.py). New turns use `PIVOT_RESEARCH`, `ConversationMode.FRESH`, and `stateless_external=True`, and recheck external permission before calling the conversation service at [`bridge_investigator.py:642-852`](backend/src/cti_app/application/bridge_investigator.py). `ModelConversationService.add_turn` stores the input blob, turn/run identity, and output reference/hash around the gateway call at [`model_conversations.py:1086-1365`](backend/src/cti_app/application/model_conversations.py). The model-conversation contract says turns are immutable and `primary_evidence=false`, with external permission checked per turn: [`docs/model_conversations.md:1-21`](docs/model_conversations.md), [`docs/model_conversations.md:63-99`](docs/model_conversations.md).

7. **Raw response → advisor-call artifact.** On a succeeded transport, raw output is separately archived in `model-outputs` and bounded/parsed only after archive at [`investigation_advisor_tools.py:784-886`](backend/src/cti_app/application/investigation_advisor_tools.py). The parser receives raw response text; raw bytes remain in the model-conversation output and output blob. The resulting `operator-advisor-call.v1` observation records consultation metadata, hashes, blob references, dossier/completeness and bridge provenance at [`investigation_advisor_tools.py:901-1071`](backend/src/cti_app/application/investigation_advisor_tools.py). The raw response is therefore a versioned consultation artifact, not a canonical observation promoted into the case’s primary evidence set.

8. **Parsing and refusal preservation.** `_submission_result` blocks parsing for blocked, ambiguous or unsuccessful transport outcomes, hashes the raw output and dispatches parsing at [`investigation_advisor_tools.py:2949-3168`](backend/src/cti_app/application/investigation_advisor_tools.py). Typed response parsing uses `advisor-response.v3` / `advisor-source-parser.v3` at [`advisor_contracts.py:17-18`](backend/src/cti_app/application/advisor_contracts.py), with typed refusal handling at [`advisor_contracts.py:46-103`](backend/src/cti_app/application/advisor_contracts.py) and [`advisor_contracts.py:445-505`](backend/src/cti_app/application/advisor_contracts.py). The tool also retains a legacy v2/wire parser path at [`investigation_advisor_tools.py:4689-4780`](backend/src/cti_app/application/investigation_advisor_tools.py) and [`investigation_advisor_tools.py:5067-5105`](backend/src/cti_app/application/investigation_advisor_tools.py). A refusal becomes `advisor_status=refused` and a partial tool result; invalid output is failed/partial as appropriate, while its raw artifact is still retained. Raw output text is cleaned only for Bridge/UI markers before parsing (`sanitize_bridge_output_text` at [`production_parsers.py:48-54`](backend/src/cti_app/application/production_parsers.py)).

9. **Reparse from stored evidence, without consultation.** `ReparsePersistedAdvisorOutputTool.execute` accepts a prior advisor-call observation, verifies its output hash and reparse context, retrieves the existing `model-outputs` bytes, checks length/hash, and reparses locally at [`investigation_advisor_tools.py:3414-3787`](backend/src/cti_app/application/investigation_advisor_tools.py). It records a new parser-version observation linked by `reparsed_from_observation_id`, retaining the same bridge turn/output SHA and recording `bridge_turns_consumed=0`. There is no provider call or new consultation in this path. The admitted reparse types are `yara_draft`, `draft_text`, `review_text`, and `figure_plan`; although captured reparse context also includes Suricata draft data, `suricata_draft` is absent from the accepted type list (`investigation_advisor_tools.py:3442-3487`, `4188-4225`).

10. **Advisor text → versioned analyst opinion (operator-mediated).** The advisor can return a draft or review artifact, but the operator-facing adapter owns compose/revise/note commands at [`analyst_opinion_service.py:1454-1654`](backend/src/cti_app/application/analyst_opinion_service.py). `compose_from_findings` creates or advances a draft with deterministic opinion identity, source synthesis/base-publication identity and Bridge provenance validation at [`analyst_opinion_service.py:262-376`](backend/src/cti_app/application/analyst_opinion_service.py); `revise` uses expected opinion version and content SHA before appending a new version at [`analyst_opinion_service.py:378-479`](backend/src/cti_app/application/analyst_opinion_service.py). Bridge draft/review references are checked against persisted advisor-call observations and exact text/target hashes at [`analyst_opinion_service.py:917-1184`](backend/src/cti_app/application/analyst_opinion_service.py). Opinion domain identity/content hashing is defined at [`analyst_opinion.py:552-627`](backend/src/cti_app/domain/analyst_opinion.py) and [`analyst_opinion.py:739-776`](backend/src/cti_app/domain/analyst_opinion.py); PostgreSQL append-only version/CAS expectations are documented at [`docs/investigation_contracts.md:37-47`](docs/investigation_contracts.md) and [`docs/investigation_contracts.md:79-129`](docs/investigation_contracts.md). Preview renders a selected current version without mutating canonical opinion state at [`analyst_opinion_preview.py:81-302`](backend/src/cti_app/application/analyst_opinion_preview.py).

## Repeated responsibilities, bypasses, and evidence loss points

### Verified overlaps / separate paths

- **External disclosure rechecks:** the same case-level allow condition is evaluated by `InvestigationService._external_allowed` and at the submission/transport boundaries (`bridge_investigator.py:270-277`, `661-667`). This is repeated enforcement of a shared policy result at distinct boundaries. It is not evidence of different policy definitions.
- **Operational-secret filtering overlaps:** the main advisor path uses `publication_secret_guard` plus dossier field-name/content omission. The sibling P10 invariant proposal path has its own `_bounded_json` and URL/text scrubbers (`invariant_proposals.py:2205-2364`), duplicating some intent with different rules. P10’s scrubber is not settings-aware for dynamic secret values.
- **Dossier recomputation:** `advisor_wire_aliases` calls `build_advisor_dossier` (`advisor_wire.py:90-264`) even when a dossier has already been built; a supplied manifest is reused, but selection/render inputs may be recomputed. This is redundant implementation work rather than a second independent completeness gate.
- **P10 is a sibling consultation path:** `invariant_proposals.py` uses its own snapshot, disclosure routing, redaction, wire parser and registry handoff; it does not pass through the main `advisor_dossier` completeness gate. That path is separately governed, not a bypass inside `advisor.consult`.
- **Checkpoint metadata is not advisor evidence:** `advisor_checkpoint.py:17-184` parses local tool-purpose trace markers and creates a bounded summary. Its `denied`/recommendation statuses describe local dispatch/coverage, not the model’s response refusal, and it does not establish CTI facts.

### Verified refusal handling and a sibling-path refusal gap

- In the main typed advisor parser, an explicit refusal is preserved as `advisor_status=refused`; the tool returns a partial result, and the raw output is retained. Invalid structure is not treated as a successful opinion/evidence result.
- **P10 wire refusal can be erased while candidates proceed [VERIFIED, high risk].** `invariant_proposals.py:1226-1342` turns `STATUS: refused` into a warning string, while still parsing candidate lines. The domain `ProposalResponse` has no refusal/status field (`domain/invariant_proposals.py:229-243`), and `propose` passes parsed candidates to P09 (`invariant_proposals.py:262-275`, `884-918`) without a refusal-status gate. Thus a refusal plus candidate lines may still reach proposal registration; the refusal reason is not modeled as a refusal outcome. The existing P10 tests located below cover forbidden external calls and unrecognized output, but no refusal-with-candidates test was found.

### Truncation, erasure, omission, and over-redaction

- Dossier extraction intentionally omits operational field names, selected metadata keys, `sha256` and `_id` keys, and raw/command-oriented fields (`advisor_dossier.py:207-225`). These are not necessarily harmful, but generic omitted fields do not each receive a manifest entry explaining their omission. A selected observation can therefore be represented only by recognized excerpts and provenance; the full source body is not guaranteed to travel.
- Selection can omit non-lexical evidence. The completeness preflight reports recognized missing/omitted source facts and contradictions (`advisor_dossier.py:942-1687`), but its visibility is bounded by what the projection/extractor recognizes.
- The main consultation’s prompt fitter is a no-op (`investigation_advisor_tools.py:3826-3844`); oversized/critical cases are rejected by preflight, not silently clipped. Editorial batching can select smaller coherent units. The raw model response is archived before the output-size parse limit is enforced (`investigation_advisor_tools.py:837-868`), so a large invalid response is preserved even when not parsed.
- The secret guard can redact recursively and fail closed on residual known operational secrets (`publication_secret_guard.py:118-153`). Dossier extraction also drops secret-like/operational fields. Consequently source facts could be over-redacted if names/content resemble secret material; there is no per-field restoration path described in this flow.
- **Restricted sample metadata projection [INFERENCE, verify policy intent].** Restricted sample-linked observations/findings are filtered, but `_sample_inventory` enumerates association IDs, short hashes, MIME types, sizes, status and engine names (`investigation_advisor_tools.py:2376-2446`). This inventory is included in plan/pivot/YARA consultation data (`investigation_advisor_tools.py:1638-1648`, `2143-2155`) without the same `_sample_policy_allows_external` check used for sample content. If sample policy covers metadata as well as bytes/content, association metadata can cross the disclosure boundary despite content filtering.
- Parser sanitization strips Bridge/UI marker lines for normalized parsing; raw output is still retained. Structural invalidity may yield only a structural excerpt in the normalized error (`investigation_advisor_tools.py:5442-5497`), which is why the raw blob and output SHA remain the audit source.
- Explicit refusals must remain outcomes. The main advisor typed path does so. The P10 sibling behavior above is the counterexample: a refusal marker is only a warning and candidate proposals can continue.

## Confidence labels and open questions

- **VERIFIED:** The main advisor path has separate projection, dossier selection, completeness, secret/policy disclosure, serialization, transport, output persistence, parsing and opinion-version stages at the cited code locations. Reparse uses stored output and consumes zero bridge turns. Model-conversation turns are documented as `primary_evidence=false`.
- **VERIFIED:** Main typed advisor refusals survive parsing as refusal status. P10 wire refusal does not currently gate candidates before P09 handoff, as traced above.
- **INFERENCE:** Sample association metadata may be disclosable under a sample-level restriction because inventory projection is broader than the content filter; policy intent on metadata scope needs confirmation from the governing contract.
- **UNKNOWN:** The requested docs define model-conversation and analyst-opinion versions, but do not define a single canonical advisor consultation/dossier/parser version contract. The relationship among `advisor-consult.v1`, `advisor-wire.v1`, legacy `advisor-response.v2`, typed `advisor-response.v3`, and `advisor-source-parser.v3` is enforced chiefly by code constants and call paths.
- **UNKNOWN:** Whether every generic dossier omission should be visible in an omission manifest, and whether sample metadata is restricted alongside sample bytes, are contract questions not resolved by the inspected files.
- **UNKNOWN:** The discovered tests are mostly fake/in-memory boundaries. This inspection did not establish an end-to-end test that joins real provider transport, durable PostgreSQL model-conversation persistence, raw blob archive, reparse, and versioned analyst opinion in one flow.
