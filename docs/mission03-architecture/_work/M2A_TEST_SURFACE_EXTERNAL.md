## Current implementation facts

- Operator admission persists a RUNNING invocation and reservation before dispatch (backend/src/cti_app/application/investigation_service.py:1040-1153). Its pre-dispatch callback reads the current envelope and checks reservation and advisor disclosure state before adapter entry (1190-1237). This is a read/check callback; it does not consume a durable, one-use permit or atomically bind dispatch to the persisted invocation state.
- The generic dispatcher accepts an optional pre_dispatch_check and enters adapter.execute after it returns (backend/src/cti_app/application/investigation_tools.py:412-427, 680-784). There is no permit type or permit consumer in the application/repository search.
- An existing RUNNING invocation replay is moved to NEEDS_REVIEW without redispatch (backend/src/cti_app/application/investigation_service.py:1079-1098). This is a useful replay policy, but no consume-time check verifies that a paused original worker is still RUNNING after another worker changes it to NEEDS_REVIEW.
- BridgeInvestigator.turn takes a boolean external_llm_allowed. Its optional before_submission callback is called before and after pacing for each transport submission (backend/src/cti_app/application/bridge_investigator.py:1172-1270). Retries and corrective submissions can therefore create multiple external sends within a logical Bridge turn; one Bridge turn budget reservation is made by the service (backend/src/cti_app/application/investigation_service.py:610-672). No per-send permit is consumed.
- Current operator effect identity is a heuristic: _semantic_parameters_fingerprint explicitly canonicalizes advisor inputs and vt.file_report.file_hash, while other tool parameters fall through to canonical JSON (backend/src/cti_app/application/operator_tool_invocation.py:1330-1398). Existing tests cover selected equivalences, not a prepared, normalized effect identity shared by permit and adapter.
- Revocation and admission use envelope version checks, but the dispatch callback itself reads current state and then returns to the dispatcher before adapter entry. The existing tests arrange revocation before that read; they do not serialize concurrent revocation and consume.

## MISSING_ORACLE list and proposed first assertions

These are gaps in the current test surface, not proposed tests already written.

1. **MISSING_ORACLE — external dispatch refused without effective authorization.**  
   **Exact seam:** InvestigationService.execute_tool_call → RegistryToolDispatcher → each external adapter entry.  
   **First assertion:** invoke with no persisted G2 envelope (and separately with provider disallowed, expired/revoked disclosure, TLP RED/do_not_submit, and zero remaining budget); assert the permit consumer rejects and every provider/Bridge spy remains at zero calls. Assert the persisted invocation and reservation have the contractually correct terminal state.

2. **MISSING_ORACLE — forged, copied, replayed or misbound permit.**  
   **Exact seam:** permit issuer/consumer binding invocation ID, investigation ID, normalized effect digest, envelope version, and reservation.  
   **First assertion:** take a valid permit and alter one binding or use it for a second invocation; assert consume rejects, the permit remains unusable, and transport count remains zero. Repeat with second consumption of the original permit.

3. **MISSING_ORACLE — concurrent revocation versus consume.**  
   **Exact seam:** PostgreSQL transaction that consumes a permit and the transaction that revokes the envelope.  
   **First assertion:** pause the dispatch worker before consume, commit revocation in a second PostgreSQL session, resume the worker, then assert consume rejects and transport count is zero. Also test the opposite serial order and assert only the explicitly defined in-flight scope may proceed.

4. **MISSING_ORACLE — RUNNING → NEEDS_REVIEW before consume.**  
   **Exact seam:** persisted invocation state check inside the same transaction as permit consume.  
   **First assertion:** worker A commits RUNNING plus reservation and pauses; worker B replays and commits NEEDS_REVIEW; resume A and assert zero permit consumption and zero transport calls.

5. **MISSING_ORACLE — crash after reservation or after consume.**  
   **Exact seam:** PostgreSQL invocation/reservation/permit transaction and dispatch recovery.  
   **First assertions:** crash after reservation but before consume, restart, and assert no egress occurred and no stale RUNNING operation can dispatch; crash after consume but before transport or response, restart, and assert the same permit cannot be consumed again and no second egress is created. Persist a deterministic recovery or NEEDS_REVIEW state.

6. **MISSING_ORACLE — ambiguous external outcome cannot automatically double-submit.**  
   **Exact seam:** permit consumer plus external transport outcome journal.  
   **First assertion:** fake provider accepts one request then drops the response; replay the invocation and assert persisted NEEDS_REVIEW, one consumed permit, and exactly one accepted request after replay.

7. **MISSING_ORACLE — normalized effect identity for equivalent requests.**  
   **Exact seam:** preparation/normalization shared by idempotency admission, permit binding and actual adapter payload.  
   **First assertion:** two raw requests that normalize to the same adapter request produce the same effect digest and cannot acquire a second permit; a materially changed normalized request produces a distinct digest. Include VT, Shodan, acquisition, Retrohunt and advisor canonicalization.

8. **MISSING_ORACLE — repeated egress inside one Bridge turn.**  
   **Exact seam:** BridgeInvestigator.turn before every InvestigationTurnTransport.submit, covering pre-submission retry and corrective-output loops.  
   **First assertion:** let the first submission succeed, then revoke or exhaust the authorized scope before the next attempt; assert the second submit is blocked unless the contract explicitly defines a consumed permit as covering the full bounded turn. Assert actual submit count and consumed permit count.

9. **MISSING_ORACLE — provenance and budget of reused results.**  
   **Exact seam:** result reuse from an existing external effect into a later invocation.  
   **First assertion:** reuse one persisted result from invocation A in invocation B and assert B links to the canonical observation/effect digest and source version, A's provenance remains intact, B is auditable, and the documented budget delta is applied exactly once without a new transport call.

10. **MISSING_ORACLE — no-permit entry at every raw adapter/transport.**  
    **Exact seams:** VT _FileReportAdapter / VT client; Shodan host/search/domain/count adapters / Shodan client; _DownloadSampleAdapter / acquisition download port; _RetrohuntToolAdapter / Retrohunt submit provider; InvestigationAdvisorTool / advisor Bridge transport; BridgeInvestigator.turn / InvestigationTurnTransport.submit.  
    **First assertion:** parameterize direct calls at each raw entry with no permit and assert fail-closed before HTTP/provider submission (spy count zero). Then pass a correctly bound permit and assert one call. Caller-level tests through RegistryToolDispatcher do not substitute for these entry checks.

## Fakes and tests that can miss a removed guard

- Operator, governance, service, B1 admission, BridgeInvestigator and adapter application tests primarily use in-memory repositories, fake ports, or scripted transports. Their deny assertions are useful for the exact caller path but do not prove a shared raw-entry guard.
- backend/tests/test_virustotal_adapter.py and backend/tests/test_shodan_adapter.py use httpx.MockTransport to assert request/response contracts. They will still pass if authorization is absent because they do not model an authorization permit.
- backend/tests/test_virustotal_retrohunt_client.py tests the HTTP client with MockTransport. It can remain green if callers can directly reach the submit client without permit.
- backend/tests/integration/test_investigation_persistence_postgres.py::test_concurrent_operation_key_replay_creates_one_invocation proves one row, not one external dispatch; it can remain green if a dispatcher double-sends.
- Positive fake-transport tests (including Bridge/advisor request wiring) assert that authorized-looking fixtures reach a fake. They do not require any permit to exist or be consumed.
- The PG integration cases prove real database persistence and selected workflow behavior. Fake egress means none proves that an actual provider accepted a request; the explicitly unapproved-envelope PG case does prove that its fake VT port is not called on that tested path.
