## 1. Chemin réel `advisor.consult`

```text
POST /investigations/{id}/operator/tools/advisor.consult
  → OperatorToolInvocationService.invoke (idempotence, état, envelope)
  → InvestigationService.execute_tool_call (cost_model fixe; tentative de réserve)
  → RegistryToolDispatcher.dispatch (réserve une seconde fois; admission avant adapter)
  → InvestigationAdvisorTool.execute
      → _check_advisor_limits (bridge_turns G2 seulement)
      → preuves / dossier / redaction / préflight 4 MB / archive du prompt
      → submit_bridge_consultation_once (pacer, une soumission)
      → ModelConversationTurnTransport → ModelConversationService.add_turn
      → ModelGateway / adapter Bridge / réponse et ModelRun persistés
      → archive du brut → parse advisor → observation d’avis non fiable
  → réponse ToolInvocation; éventuel advisor.reparse relit le blob brut sans appel Bridge
```

## 4. Mesures disponibles et estimation de coût

Le coût actuel de `tool_seconds` est pessimiste et constant: le maximum configuré de 3 600 s est réservé pour chaque type d’action, sans distinguer le dossier, la taille ou le type de consultation (`backend/src/cti_app/application/investigation_advisor_tools.py:2931`, `backend/src/cti_app/application/investigation_advisor_tools.py:3580`). Les bytes et tokens de contexte sont aussi réservés à leur plafond, puis la consommation est réduite à la taille réellement rendue (`backend/src/cti_app/application/investigation_advisor_tools.py:2933`, `backend/src/cti_app/application/investigation_advisor_tools.py:2934`, `backend/src/cti_app/application/investigation_advisor_tools.py:2696`).

Pour une politique mesurable, `model_runs` conserve `duration_ms`, `usage`, modèle, statut et état de soumission (`backend/src/cti_app/infrastructure/database/models/model_execution.py:82`, `backend/src/cti_app/infrastructure/database/models/model_execution.py:94`, `backend/src/cti_app/infrastructure/database/models/model_execution.py:96`, `backend/src/cti_app/infrastructure/database/models/model_execution.py:120`). `model_conversation_turns.model_run_id` relie le tour Bridge au run (`backend/src/cti_app/application/model_conversations.py:1280`, `backend/src/cti_app/application/model_conversations.py:1291`). `ModelUsage` porte input/output/total tokens avec un booléen `estimated` (`backend/src/cti_app/domain/model_runs.py:56`, `backend/src/cti_app/domain/model_runs.py:61`). L’observation advisor stocke déjà des estimations `ceil(bytes/4)` (`backend/src/cti_app/application/investigation_advisor_tools.py:775`, `backend/src/cti_app/application/investigation_advisor_tools.py:783`).

Limite d’instrumentation: `ModelConversationTurnTransport` retourne l’identifiant du tour mais ne remplit pas `TurnSubmission.provider_usage` (`backend/src/cti_app/application/bridge_investigator.py:569`, `backend/src/cti_app/application/bridge_investigator.py:575`); l’observation advisor marque donc l’usage absent si le transport ne l’expose pas (`backend/src/cti_app/application/investigation_advisor_tools.py:681`, `backend/src/cti_app/application/investigation_advisor_tools.py:4094`). Les mesures canoniques doivent être jointes via le tour vers `model_runs`, sans assimiler les tokens estimés à des tokens facturés. Aucun tarif monétaire/facture fournisseur n’est modélisé par `BudgetDimension` (`backend/src/cti_app/domain/investigation.py:101`).

**Option minimale B1 :** estimer `tool_seconds` par `consultation_type`, à partir d’une fenêtre versionnée de `ModelRun.duration_ms` et des tailles d’entrée; publier la méthode, les échantillons et le niveau de confiance. Réserver une borne conservatrice avec la même barrière `budget.reserve`; si l’estimation dépasse le reste G2, refuser. Pour éviter qu’une réservation plus basse ne masque une attente plus longue, borner aussi le timeout de l’appel à la réservation admise ou garder le fallback 3 600 pour les types sans données. Une proposition de borne à l’opérateur peut remplacer l’estimateur, mais reste soumise aux mêmes limites G2; aucune option n’augmente l’enveloppe ni ne contourne `reserve`.
