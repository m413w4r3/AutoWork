## 404 du proxy : cause racine confirmée (Lot B3)

Mesure opérateur depuis le worker déployé, sur un hash autorisé et sans conserver de secret : les routes sans query (`/files/{hash}`, `/files/{hash}/download`, `/files/{hash}/download_url`, `/users/me`, `/domains/x`) renvoyaient 404 (ou 400 pour le domaine). Le proxy ajoute aveuglément `&apikey=<clé>` à l’URL brute ; sans query initiale, ce fragment est concaténé de façon incorrecte et peut être interprété comme partie du chemin/identifiant. L’erreur de domaine exposait notamment `b'x&apikey=…'`. Les routes déjà envoyées avec `limit=…` fonctionnaient, ce qui avait masqué le défaut.

Correction transport : pour les requêtes **proxy-v3 uniquement**, les appels sans paramètres reçoivent le paramètre inoffensif `x=1`, activé par défaut via `VIRUSTOTAL_PROXY_QUERY_SENTINEL_ENABLED=true`. Les requêtes ayant déjà une query la gardent. Le transport direct v2 conserve ses paramètres `apikey` et `hash` sans sentinelle. Les événements et routes normalisées ne contiennent jamais la query ; les empreintes de scope changent quand le réglage change.
